1. الغرض من الوثيقة

هذه الوثيقة تحول الـBlueprint العام إلى مواصفات قابلة للتنفيذ والاختبار. لكل وحدة يتم تحديد الشاشات، الحقول، الإجراءات، الصلاحيات، الحالات، قواعد العمل، والـWorkflow. يجب اعتبارها المرجع الوظيفي قبل كتابة الكود.

أي قرار غير مذكور هنا لا يجوز للـAI أو المطور اختراعه؛ يتم تسجيله كـOpen Decision أو Change Request.

2. نطاق النظام

نظام داخلي لإدارة الدائرة السريرية.

لا توجد حسابات للطلاب في المرحلة الأولى.

يدخل العميد، نائب العميد، مدير الدائرة، المساعد الإداري، رؤساء الأقسام، مساعدو البحث والتدريس، المشرفون السريرييون، المرشدون، الجودة، ومدير النظام حسب الصلاحيات.

النظام عربي/English.

البيانات التاريخية مهمة ويجب عدم حذفها فعليًا.

11.1 Suggested Distribution Engine

Inputs: students, groups, sites, supervisors, availability, capacity, rotation dates, rules.

Hard Constraints: لا تعارض زمني، لا تجاوز سعة، لا مشرف غير متاح.

Soft Constraints: التوازن، التوزيع العادل، تفضيلات يمكن اعتمادها.

Output: Proposed Distribution + Conflict Report.

المستخدم يراجع ويعدل قبل الاعتماد.

33. قواعد العمل مع Cursor / Claude / Antigravity

لا تبدأ من Prompt عام؛ أعطِ Architecture + هذا الملف + ERD.

نفذ Module واحد في كل مرة.

قبل الكود: اطلب من AI عرض فهمه للـRequirements.

لا تسمح له بتغيير Schema سابق دون Migration وخطة تأثير.

كل Feature لها Tests.

كل Permission لها Test.

كل Workflow له Test.

أي Business Rule جديدة تسجل في Change Log.

لا تستخدم بيانات حقيقية أثناء التطوير إلا وفق سياسة الجامعة.

قبل Production: Security Review + Backup/Restore Test + UAT.

34. التسلسل المقترح للعمل من الآن

تثبيت هذا الملف واعتماد Open Decisions.

استخراج Data Dictionary كامل من Excel.

عمل ERD احترافي.

عمل Permission Matrix كاملة لكل Screen/Action.

عمل Workflow Diagrams للمراسلات والاعتمادات والتوزيع والدرجات.

عمل Wireframes للشاشات الرئيسية.

اختيار Architecture النهائي.

إنشاء مشروع Git.

بناء Foundation.

بدء Students ثم Staff/Sites ثم Curriculum ثم Clinical Engine ثم Assessment/Grades ثم Advising/Quality ثم Correspondence/Reports.

تنفيذ UAT مع مدير الدائرة في كل مرحلة.

35. الخلاصة التنفيذية

هذه الوثيقة هي الجسر بين فكرة النظام والبرمجة. إذا تم اعتمادها، فإن الخطوة التالية ليست كتابة Prompt للـAI مباشرة، بل بناء ثلاثة مخرجات هندسية: Data Dictionary، ERD، وPermission/Workflow Matrix. بعدها يمكن إعطاء Cursor أو Claude أو Antigravity مهام دقيقة قابلة للاختبار بدل أن يبني النظام بطريقة عشوائية.
